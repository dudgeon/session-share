Session navigator

Long Claude Code sessions get unwieldy. Search and collapse-all help, but readers still scroll a lot to find the prompt they remember. The "TOC / scrubber" slot in BRIEF.md §9 is unfilled. Here are five candidates with trade-offs and a pick at the end.

1. Inline contents disclosure

A <details> block at the top of the session, listing every user prompt as a clickable link to its id="node-…" anchor. Closed by default; open shows a 1-line preview per prompt.

  • Simplest possible. Semantic HTML, prints well, accessible by default.
  • Zero layout disruption. Works on mobile without changes.
  • Inherently part of the artifact — also visible in exported HTML with no extra plumbing.
  • Only useful before scrolling. Mid-session you'd have to scroll back to use it.
  • Doesn't show your current scroll position.
~30 LOC half a day no layout reflow

2. Floating prompt-jump dock

A small icon button pinned to the bottom-right corner. Click opens a compact popover listing every user prompt; the one closest to the viewport is highlighted. Click a row to scroll-jump.

  • Always reachable, no matter where the user is in the document.
  • Tracks current position automatically (IntersectionObserver on prompts).
  • Doesn't conflict with the existing comment rail or any layout grid.
  • Mobile-friendly: a single tap target.
  • Hidden by default — discoverability depends on the icon being recognizable.
  • Slight SaaS-y feel; needs careful styling to fit the marginalia aesthetic.
~120 LOC ~half a day no layout reflow

3. Right-edge minimap

An 8-12px vertical strip pinned to the viewport's right edge. Each node renders as a colored bar (taller for prompts, shorter for tool calls). A translucent box marks the visible viewport. Click anywhere to jump.

  • Communicates session shape and density at a glance — long sessions feel quantified.
  • Live position indicator without click.
  • Click-to-jump anywhere with sub-second targeting.
  • Conflicts spatially with the comment rail when comments exist; needs careful placement (further right? above the rail?).
  • Not very discoverable for first-time users; bars don't carry labels.
  • Click targets are small — easy to misclick on long sessions.
~200 LOC 1-2 days layout: nudges rail

4. Sticky top progress bar with prompt ticks

A thin horizontal strip pinned below the toolbar. The fill represents scroll progress; tick marks represent user prompts. Hover a tick → preview tooltip; click → jump.

  • Reinforces "how far through am I?" — a metric search and TOCs don't surface.
  • No conflict with the right rail.
  • Naturally aligns with the toolbar's existing sticky positioning.
  • Steals 4-8px of vertical real estate from the reading column on every page.
  • Tick density gets unmanageable past ~30 prompts (overlap, hover cone confusion).
  • Visually loud — the filled bar reads like a video player, not a document.
~150 LOC 1 day vertical real estate cost

5. Persistent left-rail TOC

A permanent sidebar to the left of the conversation column, listing all user prompts. Active prompt highlighted by scroll position. Click to jump.

  • Highest information density — full prompt text visible.
  • Always present, easy to discover, mirrors a familiar Notion/Docs pattern.
  • Symmetrical with the comment rail (TOC left, comments right).
  • Big layout cost: needs ~200px on the left, breaks the centered reading column on screens narrower than ~1400px.
  • Forces a 7-column grid (TOC + col + gap + rail) when comments exist; mobile collapse gets tricky.
  • Loud — the rail competes with the body for visual weight.
  • Doesn't work as well in printed/exported view; would need to be hidden.
~250 LOC 2-3 days layout: significant reflow

Recommendation

Ship #2 (floating dock) as the primary navigator, with #1 (inline disclosure) as a complementary at-a-glance overview.

The pair fills both jobs without disrupting layout: the inline disclosure is visible immediately and prints well, while the floating dock keeps navigation always-accessible mid-session and tracks scroll position. Neither conflicts with the comment rail. Total cost is comparable to #5 alone, and the result fits the marginalia aesthetic better than a minimap or progress bar.

Suggested rollout

  1. Phase 1 — inline disclosure (½ day). A single <details> in SessionHeader, rendering an anchor link per user prompt. Each link uses the existing id="node-{id}". Print-friendly, works in exported HTML for free.
  2. Phase 2 — floating dock (½–1 day). A new NavDock component in ui.jsx, position: fixed; bottom-right. Click toggles a popover listing prompts. Use IntersectionObserver on each prompt's NodeRow to compute the active prompt. Hide in edit mode (where the toolbar's "expand all" already serves a similar role).
  3. Phase 3 — polish. Keyboard shortcut (g g) to focus the dock; Esc to close; smooth-scroll on click; hide both pieces on sessions with fewer than ~5 prompts (overhead exceeds value).
